# Flop Club — словарь данных и бизнес-вопросы

Экспорт: `flop_coursework_safe_export_20260906`. Период данных: 2026-06-05 — 2026-09-13.
5 таблиц, связи см. в `import_schema.sql`.

## tournaments — карточки турниров (55 строк = 46 FINISHED + 8 OPEN)

| Поле | Значение |
|---|---|
| `id` (PK) | Слаг турнира: `дата-название`, напр. `2026-06-05-flop-grand-openning` |
| `title` | Название турнира |
| `description` | Анонс/описание (маркетинговый текст) |
| `starts_at` | Дата и время старта |
| `location` | Место проведения (всегда «Flop Club, Барнаул») |
| `buy_in` | Стоимость входа. 0 — фрироллы |
| `re_entry` | Стоимость повторного входа после вылета |
| `prize_pool` | Пул **очков рейтинга**, разыгрываемый между призовыми местами турнира — это НЕ деньги (денежный гэмблинг в клубе запрещён) |
| `rating_pool` | Отдельный пул **рейтинговых очков** — не деньги, другая механика |
| `rating_series_month` | Месяц рейтинговой серии (в экспорте почти всегда пусто) |
| `entries_count` | Итоговое число входов на момент экспорта |
| `profile` | Формат: BASE, DEEP_SPECIAL, KNOCKOUT, FREEZE, TURBO_ACTION, FINAL, PHOENIX |
| `late_registration_ends_at` | Дедлайн поздней регистрации |
| `add_on_enabled` | Доступна ли докупка фишек |
| `add_on_price` / `add_on_chips` | Цена и объём докупки |
| `max_participants` | Лимит участников |
| `status` | FINISHED / OPEN |
| `allow_cancellation` | Можно ли отменить регистрацию |
| `created_date` | Дата создания турнира в системе |

## players — анонимизированные игроки (191 строка)

| Поле | Значение |
|---|---|
| `player_id` (PK) | Искусственный ID `player_NNN` |
| `display_name` | Анонимное имя «Игрок N» |
| `rating_points` | Суммарные рейтинговые очки |
| `knockouts` | Сумма зачтённых нокаутов игроку (см. ограничение по таблице `knockouts` ниже — почти всегда 0) |
| `tournaments_played` | Сколько турниров сыграно всего |
| `tournament_wins` | Сколько раз занял 1-е место |

## registrations — регистрации на турниры (835 строк)

| Поле | Значение |
|---|---|
| `registration_id` (PK) | ID регистрации |
| `player_id` (FK) | Игрок |
| `tournament_id` (FK) | Турнир |
| `status` | ACTIVE / CANCELLED |
| `live_status` | IN_GAME / ELIMINATED — текущее игровое состояние на момент экспорта |
| `finish_place` | Итоговое место. Пусто у ~16% строк — почти все из-за незавершённых/`OPEN` турниров; среди сыгранных (`FINISHED`) пусто только у 30 строк, и 29 из них — один турнир (первое открытие клуба, `checked_in='t'` у всех) — пробел логирования, **не индикатор неявки** |
| `entry_number` | 1 — первый вход, 2+ — ре-энтри после вылета |
| `add_on_count` | Сколько раз докупил фишки |
| `checked_in` | Отметился ли на регистрации: строки `'t'`/`'f'` (Postgres CSV-формат, **не Python bool**) — используй для no-show |
| `created_date` | Дата создания регистрации |

## rating_results — рейтинговые результаты (435 строк)

Заполняется не по всем участникам турнира, а только по призовой зоне (в среднем ~9-10 строк на турнир, т.е. топ ~25-30% от посадки).

| Поле | Значение |
|---|---|
| `tournament_id`, `player_id` (составной PK) | Турнир + игрок |
| `place` | Место в этом турнире (в рамках призовой зоны) |
| `percent` | Доля пула очков, доставшаяся месту |
| `points` | Абсолютные очки за место |
| `knockouts` | Нокауты именно в этом турнире |
| `created_date` | Дата фиксации результата |

## knockouts — связи нокаутов (⚠ 3 строки на весь период)

| Поле | Значение |
|---|---|
| `knockout_id` (PK) | ID записи |
| `tournament_id` (FK) | Турнир |
| `eliminated_registration_id` (FK → registrations) | Кого выбили |
| `killer_registration_id` (FK → registrations, nullable) | Кто выбил |
| `created_date` | Дата |

**Ограничение данных**: таблица покрывает 1 турнир из 46 завершённых — почти наверняка дефект логирования этой механики, а не факт о клубе. Не стройте метрики нокаутов на этой таблице; поле `players.knockouts` и `rating_results.knockouts`, скорее всего, тоже занижены по той же причине.

**Ещё одно ограничение**: последний турнир в выгрузке — 2026-09-13. Сентябрь как месяц неполный — сравнивать его с июнем/июлем/августом напрямую (без нормализации на число дней/турниров) некорректно.

**Про LTV**: `prize_pool`/`rating_pool` и `rating_results.percent`/`points` — это очки рейтинга, не деньги (денежный гэмблинг в клубе запрещён). Единственные денежные поля — `buy_in`/`re_entry`/`add_on_price`. Поэтому посчитанный LTV — это **revenue to date** (накопленные траты игрока: бай-ины + ре-энтри + аддоны), а не чистая прибыль клуба с игрока: выигрышей в деньгах в этой системе просто не существует.

## Бизнес-вопросы по блокам

### 1. Рост и посещаемость
- Растёт ли число турниров и участников от месяца к месяцу?
- Есть ли сезонность (день недели, время старта)?

### 2. Удержание и отток
- Какая доля игроков возвращается после первого турнира?
- Кто входит в «ядро» аудитории (топ по частоте участия) и какую долю посещений оно даёт?
- Сколько игроков зарегистрировались, но так и не сыграли ни разу?

### 3. Юнит-экономика
- Сколько реальных денег (бай-ины + ре-энтри + аддоны) собирает клуб, и как это распределено между игроками?
- Как ре-энтри и аддоны влияют на выручку с турнира?
- Есть ли связь между размером бай-ина и числом участников (ценовая эластичность)?

### 4. Форматы турниров (продукт)
- Какие форматы (`profile`) дают наибольшую посадку относительно лимита (`max_participants`)?
- Стоит ли пересмотреть бай-ины/частоту форматов с низкой посадкой?

### 5. Операционка
- Какая доля неявок (no-show) и как она соотносится с политикой чек-ина?
- Какая доля отмен регистраций и меняется ли она со временем?
